# 产品决策记录（当前无阻塞问题）

> 截至 2026-07-22，进入工程 Spike 所需的产品选择已经收敛。模型、阈值、编码、KDF、加密容器和 SDK 选择由 Spike/基准解决，不重新抛给用户。

## 已冻结：V1 最低内存

V1 最低支持 16 GB 统一内存的 Apple Silicon Mac。24 GB 及以上可根据基准启用更高质量或更高并发配置；8 GB 可做发现性实验，但不属于 V1 承诺范围。

## 已冻结：原始音频保留

口述、线下录音、电脑内录和导入的原始音频全部默认永久保留，只有用户明确删除时才移除。V1 不提供默认自动过期；额外自动保留策略以后再立项。

## 已冻结：导出、离线迁移与云同步

- 单条/单段音频从历史中按原始资产或尽量保持原格式导出，用于普通播放、分享和外部处理。
- 完整历史通过版本化、带完整性校验的加密 `.bestasrarchive` 备份与恢复，包含全部可迁移历史及原始音频，不提供明文数据库/Excel。
- 归档使用用户可携带到另一台 Mac 的口令或恢复秘密，不能只依赖来源 Mac Keychain；具体 KDF/AEAD/分块方案由 Spike 决定。
- 未来云同步使用独立 `SyncAdapter` 增量同步，不上传整个归档包作为同步协议。

## 已冻结：统一人物处理与 MVP 边界

- 口述、线下录音、电脑内录和导入媒体在人物处理上完全等价，共用同一会话说话人、出现记录、全局 Person 空间、置信分层和纠错机制；单人只是统一流程中的一个说话人簇。
- 同一次口述支持两三人或更多人轮流说话，bestASR 内部保留各自时间片段、人物关系并可分别检索；默认向目标 App 插入一份不带说话人标签的纯文字只是呈现规则。
- MVP 先交付口述用户闭环，但首个实现就使用完整 V1 的协议、领域模型、持久化、durable jobs、模型和未来同步边界；不建立待重写的 MVP 专用核心架构。

## 其他已采用、无需再确认的澄清

- V1 当前不交付在线跨设备同步；未来明确保留历史迁移及至少 iPhone↔Mac 同账号同步方向。
- 删除人物/声纹不会静默连带删除包含其他人的整场会议；历史删除走独立预览与二次确认。
- 默认无产品遥测；用户内容不进入普通日志或默认诊断包。

## 可延后到同步立项时再确认

- 使用 iCloud/Apple ID 还是产品账号。
- 默认同步文本/人物关系，还是也同步原始音频与声纹。
- iPhone 首版角色是录音/口述端、历史浏览端，还是两者都做。
- 多 Mac 同步与共享协作是否进入同一版本。
