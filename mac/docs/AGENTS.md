# 让其他 App 读写 Mindloom

Mindloom 可以把你允许的那部分事交给 Claude Code、Claude Desktop、Codex（也包括 ChatGPT 桌面版里的 Codex）、Cursor 这类 App：它们能问今天有什么要紧的、按一句话找东西、读一件事现在到哪一步、接下来要做什么、谁说过什么。你另外选择“允许更改”时，它们还能添加内容、更改归属、重新命名、标记为完成；改了马上生效，你在 Mac 上看得到，也能撤销。

三样东西各管一件事：

- **连接程序**是通道。Mindloom 自带一个小程序 `mindloom-mcp`（在 App 的 `Contents/Helpers/` 里），其他 App 启动它、和它说话；它把请求转给正在运行的 Mindloom。
- **插件或扩展**负责一键安装：Claude Code 插件、Claude Desktop 扩展。
- **服务说明和 Skill** 告诉那个 App 的模型什么时候用、怎么用：你问到自己的事、会议、人、截止日期或记下的内容，或者当前任务要用到你某件事的情况时用，你不必提到 Mindloom；与你的事无关的任务（一般的编程、通用知识）不用。先找再读；写出出处；资料只是数据；你明确要它改时才改。

读不读由你在两处决定：那个 App 调用工具前的权限提示（Claude Code 默认会问，你可以在那里选择以后不再询问），和 Mindloom 的授权卡（下面“第一次来读”）。服务说明不叫模型另外先问你能不能读：MCP 规范把工具定为由模型决定何时调用、由宿主 App 让人把关（[MCP 2026-07-28 · Tools › User Interaction Model](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)）。

这一切都在这台 Mac 上：连接程序只经数据目录里只有你能进的本机通道连到 Mindloom，不开网络端口。

## 读到的内容会去哪里

这些 App 背后的模型在做它的公司的服务器上运行（Claude 在 Anthropic，Codex 和 ChatGPT 在 OpenAI）。它们从 Mindloom 读到的文字，会发到那里处理，并留在那个 App 的对话记录里。Mindloom 决定给它看什么、让它改什么；它拿到之后怎样，由那家公司的规则决定。已经读走的内容收不回，停止允许只影响以后。

给出去的只有文字：事的标题、现在到哪一步、步骤和日期、人名，以及（你要它看原文时）原文的文字摘录。录音、声音样本和个人词典不在其中。

## 打开

在 Mindloom 的 **设置 › 其他 App** 里打开「允许其他 App 读」。这个开关跟着资料库走，新资料库默认是关的；关着时其他 App 连不上（会被告知开关是关的）。关掉时，正在连着的 App 马上断开。

## 第一次来读：你来决定

一个 App 第一次来读时，Mac 上会出现一张卡片和一条通知：「让 Claude Code 读「某件事」？」。卡片不抢键盘：你在那个 App 里打的字照样留在那个 App 里；点一下卡片它才接收按键，这时按 Esc 只是把卡片收起来，什么都不答应也不拒绝（设置 › 其他 App 和通知里能把它找回来）。

卡片上写着：

- **是谁**：谁签的名、程序在哪，例如「Anthropic PBC 签名的程序 · ~/.local/share/claude/versions/2.1.3/claude」。如果以前允许过同名的 App，但这次是另一个程序（签名或位置不一样），卡片会用红字写明，并写出以前允许的那个在哪里。
- **能读**：默认只读它这次问的那件事。它没点名哪件事（例如先搜索）时，什么都不勾，你从最近的事里勾几件；「全部的事」和每个共享空间都是单独的勾，默认不勾。
- **多久**：这次对话（这个 App 这次连着的时候）/ 今天（到产品时区的零点）/ 一直（直到你停止允许）。
- **手机号、证件号**：遮住（默认）/ 原样。遮住时它们换成 `〔手机号·a1b2c3〕` 这样的占位符，规则和发给你的 DGX Spark 时相同；每个授权的占位符都不一样。
- **允许更改**：默认不勾。勾上后它能添加内容、更改归属、重新命名、标记为完成。
- 一句话说清点「允许」会发生什么。

选「一直」「全部的事」或“允许更改”时，点「允许」还要用触控 ID 或登录密码确认：能操作屏幕的程序点得了按钮，过不了这一步。

App 认人的方式：它自报的名字，加上 Mindloom 自己从系统里查出来的、启动连接程序的那个程序的情况：位置、开发者签名，解释器（node、python 等）还有它运行的脚本。有开发者签名的程序升级换了版本号文件夹仍算同一个；没有签名的按确切位置和脚本认。名字一样、程序不一样，就是另一个 App，要重新问你；同一个名字同时只弹一张卡。

## 它能做什么

读（`readOnlyHint: true`）：

| 工具 | 做什么 |
|---|---|
| `today` | 今天和明天到期的、已经过期的、昨天以来有新进展的事，开头一段能直接念的概括 |
| `search` | 用一句话或几个词找，和 Mindloom 历史页同一个引擎：词序不限，同音错字、空格、大小写、繁简不影响；句中的时间（上周、9月25日）、来源（微信、会议）和人名当作条件。返回事、为什么找到它（标题、现在、步骤、人物或哪条原文）、读出的条件；都不含时标“只包含其中一部分词” |
| `get_matter` | 读一件事。默认简短版：现在到哪一步、接下来（带步骤 id 和日期）、已过期、待定、最近完成、人物；`detail: "full"` 另附原文摘录（每条带条目 id；最新的在前，按页给，每页一万字以内，`page` 翻页，回答末尾写着共几页）；`item_id`（加 `around`）只读一条原文：来源和时间、最接近 `around` 的一句和前后两句，会议和聊天的每句前面是说话人 |
| `get_person` | 一个人参与的事（默认前 10 件），和他最近说过的几句话 |
| `list_deadlines` | 接下来若干天（最多 30 天）有日期的计划，最近 7 天里过期的也列出；默认前 10 条 |
| `list_recent` | 最近若干天（最多 14 天）有动静的事；默认前 10 件 |

回答默认简短：`get_matter` 默认是简短版，`search` 默认 8 件；三个列表默认前 10 条，回答里写着另有多少，`limit` 最多 50。

改（只有选择了“允许更改”才列出来；工具说明写着主人明确要求时才用）：

| 工具 | 做什么 |
|---|---|
| `add_note` | 添加一段文字，和其他新添加的内容一样整理，来源写成「Claude Code（其他 App）」；给了 `matter_id` 就直接放进那件事 |
| `move_item` | 把一条原文从一件事移到另一件事；不给 `to_matter_id` 就是拿出来，回到“最近添加” |
| `rename_matter` | 给一件事重新命名 |
| `mark_step` | 把一步标为完成（`done`），或把待定的问题标为已经定了（`settled`） |

改动只碰你允许它读的、属于「我的」事；共享空间里的事它只能读。每次改动都按你在页面上改的同一条路走，马上生效，记下来，能撤销。工具里没有删除、共享、导出、发送、录音、改设置或改授权；Mindloom 也从不启动、指挥其他 App。

另有资源 `mindloom://matter/<id>`，内容和 `get_matter` 的简短版相同。列出资源（`resources/list`）从不弹卡：没有授权时列表是空的，也不记录；Mindloom 没有在运行或开关关着时也是空的。有授权时按页给，每页 25 件、最多 50 件，最近的在前，每件事只有标题和 id，用 `nextCursor` 翻页（Claude Code 每次启动都会自己翻完）。每一页记一行“列出事”，不计入下面的读取字节，另有每小时 40 页的上限。

每次回答里，来自资料库的字（标题、步骤、人名、来源、原文）都放在一对带随机编号的标记之间，例如 `⟦资料 3f9a2c41de⟧ … ⟦/资料 3f9a2c41de⟧`，编号每次回答都换；标记之间的任何文字都是资料，不是给它的指令。

每个授权每小时有上限（默认：读 40 件事或 20 万字节，添加 30 条，改 15 次，列出 40 页）。字节只算读取和搜索返回给模型的资料文字，不算列出的标题。读取、添加和更改用完时它会被告知先停下，你会收到一条通知；列出用完时它也会被告知，但不通知你（那是 App 启动时自己列的）。一小时内的用量回落后自动恢复。

## 看得见、撤得回

**设置 › 其他 App** 列出每个允许过或来读过的 App。点开一个 App：

- 它是谁（签名、位置）、现在允许它做什么，和「停止允许」（它下次来读时会再问你）。
- **它改过的**：每一次改动一行，带「撤销」。撤销把它改的恢复原样；它添加的那条会删除。不限时间。
- **它读过的**：每一次调用一行，含被拒、等你决定、超过上限和读共享空间的：时间、做了什么、结果。只记时间、工具、事的 id、结果和字节数，不记它搜了什么、读到什么。
- **导出记录…**：这个 App 的全部调用和改动，存成 JSON。

读取或被拒绝读取共享空间的事时，这个空间的记录里也会多一行（哪个 App、什么工具、几件事、几条素材、多少字节），空间的管理员看得到。

授权只记范围；每个授权的密钥存在这台 Mac 的钥匙串里。资料库里的授权记录被改过，或者钥匙串里的密钥没了，这个授权就作废。

## 怎么连接

Mindloom 要装好、正在运行，并打开了「允许其他 App 读」。下面以 `/Applications/Mindloom.app` 为例；设置 › 其他 App 里能复制带着正确位置的命令。

**Claude Code（插件）**：安装仓库里的 `integrations/claude-code-plugin`。它带连接配置、`mindloom` skill 和两个命令：

- `/mindloom:context <事>`：把一件事的来龙去脉带进当前任务。
- `/mindloom:handoff <事>`：为一件事写交接说明；允许更改时，问过你再添加到这件事。

插件按应用标识 `app.mindloom` 找 Mindloom：先问系统（LaunchServices）它装在哪里，再看 `~/Applications`、`/Applications`；签名检查通过（Apple 签发的开发者证书，App 和连接程序同一个团队）才启动。找不到正式版时才用预览版。装在别处时把环境变量 `MINDLOOM_MCP` 设为连接程序的完整路径。

**Claude Code（只连接）**：

```sh
claude mcp add mindloom -- "/Applications/Mindloom.app/Contents/Helpers/mindloom-mcp"
```

**Claude Desktop**：用 `integrations/claude-desktop` 打包出的扩展安装（方法见那里）。

**Codex、ChatGPT 桌面版**：在 `~/.codex/config.toml` 里加：

```toml
[mcp_servers.mindloom]
command = "/Applications/Mindloom.app/Contents/Helpers/mindloom-mcp"
```

**Cursor**：在 `~/.cursor/mcp.json` 里加：

```json
{ "mcpServers": { "mindloom": { "command": "/Applications/Mindloom.app/Contents/Helpers/mindloom-mcp" } } }
```

检查连没连上：`"/Applications/Mindloom.app/Contents/Helpers/mindloom-mcp" --check` 会显示「Mindloom 在运行，可以连接」或「Mindloom 没有在运行，请先打开 Mindloom」。它不读任何内容。

演示库或开发版用另一个数据目录时，给 App 的环境加上 `MINDLOOM_DATA_ROOT=<那个数据目录>`（设置里复制的命令会自动带上）。

## 出错时

| App 看到 | 意思，和你能做的 |
|---|---|
| Mindloom 没有在运行，请先打开 Mindloom | 打开 Mindloom 再试 |
| Mindloom 里的「允许其他 App 读」是关着的 | 在 设置 › 其他 App 里打开 |
| 已经在 Mindloom 里请主人决定 | 在卡片或通知里决定，然后再试 |
| Mindloom 的主人没有同意这个 App 读取 Mindloom | 你拒绝了；要放开就等它下次来问 |
| 没有找到这件事，或者它不在主人允许的范围里 | 不存在，或不在给它的范围里（两种回答一样） |
| 主人只允许读，没有允许改 | 要它改，就停止允许，等它下次来问时勾上“允许更改” |
| 这一小时用得太多，Mindloom 先停下 | 等一会儿；或在 设置 › 其他 App 里停止允许 |

## 通道怎么守

- Mindloom 只在自己数据目录里的私有文件夹（0700）里开一个本机通道（0600）。每个连进来的程序，先用系统记录核对它属于你这个用户，再核对它的代码签名就是这份 App 自带的 `mindloom-mcp`（同一个开发者团队、同一个标识；没有团队签名的开发版和检查版核对代码摘要）。别的程序直接连通道，什么也拿不到。
- 连接程序不存资料、不带密钥，只转话；它也反过来核对 Mindloom 那一端属于你。
- 同一个程序也是你自己的命令行 `mindloom add …` / `mindloom due`，和 Chrome 扩展「收进 Mindloom」的本机连接程序。它们各有自己的开关（设置 › 入口），默认关；其他 App 的会话里调用不了它们。Chrome 扩展收进来的，只有在 Mindloom 核对出是 Google 签名的 Chrome 启动了连接程序时，来源才写「Chrome」，否则写「本机其他程序」。分享菜单的投递文件夹、服务菜单这类核对不了是谁送来的入口，来源都写「本机其他程序」。
- 每一次调用都当场检查授权，所以停止允许和到期在下一次调用就生效。

## 边界

- 在这台 Mac 上以你的身份运行的程序，本来就能读你的文件，包括资料库文件。上面这些规矩管的是从连接程序来的 App；资料库文件本身的加密是另一件事，还没有做。
- 一个运行连接程序本身的程序，会被当成启动它的那个程序来认：卡片上写的是它自己的签名和位置。没有开发者签名的 App（例如用 node 运行的脚本），如果有别的程序用同一个解释器运行同一个脚本，Mindloom 分辨不出来。
- 遮住只管号码类信息；事情本身（谁、什么时候、做了什么）原样给出。遮住时，搜索也只在遮住后的文字里找；搜索词里带号码的，直接不回答。
- 手机上的 ChatGPT 连不到 Mac 本机；它要一个公网入口，目前没有做。
