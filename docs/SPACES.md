# 共享空间（Spark 端）

**一句话**：个人空间是只有一个成员的保险箱，共享空间是有 N 个成员的保险箱。钥匙只在成员的设备上；Spark 只做三件事——按顺序记下每个成员签了名的操作、替成员保管打不开的密文、在某位成员的 Mac 借给它钥匙的那段时间里，把大家共享的素材拼成一件件共享的事。

协作规则照 GitHub 的逻辑：个人拥有的小组空间像个人仓库加协作者，实验室（组织）的空间像组织仓库——贡献进来的东西是组织资产，谁贡献的永远记着。

本文是 Spark 端（本仓库）的说明和接口。Mac 端（创建、邀请、共享前的勾选清单、遮号码、解密显示）在 Mac 客户端仓库里。

## 三条规则，所有空间都一样

1. **Spark 只看到整理需要的东西。** 也就是遮过号码的文字和缩小的图，而且只在整理的时候、只在内存里，用的是某位在线成员的 Mac 借给它的钥匙（和个人空间 v6 一样的开锁方式）。
2. **人看到的是你给的。** 你共享的原件（文件、截图、会议里**一段**的录音）端到端加密给成员的设备。Spark 存密文，打不开。成员看到的号码是原样的，因为那是你愿意给他们看的；给 Spark 的那一份仍然是占位符。
3. **属于你身体和习惯的东西永远不离开 Mac。** 声纹、个人词典、个性化识别都不进任何空间。共享空间里的人只用名字认；录音只按片段共享，从不整场共享，因为一整场会议里还有别人的话。

Spark 端能做到的强制：
- 不收整场录音、声纹、词典、说话人向量这几类（`never_shared`）；带音频原件的素材必须标明是哪段录音的哪一段，最长 15 分钟（`audio_needs_segment`、`segment_too_long`）。
- 同一段录音，一个成员在一个空间里共享的所有片段（文字或音频）加起来最多 15 分钟，重叠的部分只算一次（`recording_share_limit`）：八段首尾相接的 15 分钟就是整场会议。撤回一段，它的时长就还回来。
- 送来整理的素材里，人物编号（Mac 上可能来自声纹聚类）一律换成由名字算出的编号，没有名字的人直接丢掉。
- 所有要存的密文先查外形（前缀、base64url、长度）：明文字符串、明文文件一律拒收（`not_ciphertext`）。

## 谁拥有什么（GitHub 模型）

| GitHub | 织机 |
|---|---|
| 个人仓库 | 个人空间 |
| 个人仓库 + 协作者 | **小组空间**（个人拥有）：谁共享的谁能随时撤回或删除；拥有者能移除任何素材 |
| 组织 / 组织仓库 | **组织**（实验室）/ **组织空间**：贡献进来的是组织资产 |
| Read / Write / Maintain / Admin；外部协作者 | 只读（read）/ 贡献（write）/ 维护（maintain）/ 管理（admin）；外部合作者（只在某个空间里，不是组织成员） |
| 作者离开后 commit 仍署名 | 每条素材永远记着贡献者 |
| 不能删别人在组织仓库里的 commit | 组织空间里贡献者 **24 小时内**可以撤回或换成新版本，之后只能**申请下架**（过了窗口再共享新版本也会被拒：`window_passed`，新版本会删掉旧版本的钥匙和原件）；隐私下架必须在空间规定的时限内处理（默认 72 小时），维护者不处理，Spark 到期自己执行；别人对你素材的隐私下架，维护者可以写明理由拒绝；维护者可以移除任何素材（留墓碑 + 清除） |
| Pull request / review | **提议**：贡献者提议改名、拆分、合并、挪到另一根绳、改关系；维护者接受或拒绝；AI 的合并提议走同一个队列；维护者可以直接改 |
| 私有组织仓库的 fork 在失去权限时移除 | 「存一份到我的空间」要空间规则允许（组织空间默认不允许）；失去权限后，那台设备下次同步时会被告知删掉哪些，回答里附上结束它权限的那条签名操作（`removal`），Mac 用自己从签名日志里重建的成员名单核对过才删（诚实地说：一台再也不同步的设备没法强制） |
| 成员离开 / 被移除 | 权限收回，**换钥匙**（新的一代），贡献仍署名，个人空间不受影响 |
| 转交、归档 | 把一件共享的事的**负责人**交给另一位成员；把空间**归档**成只读 |
| 组织审计日志 | 成员变动、共享、撤回、移除、Agent 读取（Agent 读到这个空间的事时，读的人的 Mac 写一条 `agent.access`：客户端名、工具、几件事、几条素材、多少字节）；管理员看得到记录，**看不到内容** |

各角色能做什么（`GET /v1/spaces/{id}` 的 `me.rights` 就是这张表）：

| 动作 | 最低角色 | 备注 |
|---|---|---|
| 看、隐藏（只对自己）、离开、记一次 Agent 读取、改自己的名字、为隐私申请下架 | 只读 | 隐私下架任何成员都能申请（内容涉及到他）；申请别人共享的素材时，一个人同时最多 3 条没处理完（`too_many_takedowns`），维护者可以写明理由拒绝；贡献者对自己素材的隐私下架不能拒绝。下架理由只给申请人和维护者看：其他成员拿到的操作日志里这一栏是空的（`withheld`），签名照样能验；存一份到自己空间要规则允许 |
| 共享素材 / 一件事 / 规则，提议，撤回自己的，把钥匙重新包到新一代，送整理素材 | 贡献 | 撤回：小组空间随时；组织空间在窗口内；「删除」在组织空间过了窗口变成下架申请 |
| 移除任何素材，处理下架申请，处理提议，直接改共享的事，转交负责人 | 维护 | 负责人自己也能把负责人转给别人 |
| 邀请、同意 / 拒绝加入、改角色、移除成员、换钥匙、改空间规则、归档 | 管理 | 小组空间的拥有者和组织管理员始终是管理；组织管理员的管理权只认他自己的组织设备（只知道他的成员编号不算）；拥有者不能被降级或移除 |

## 钥匙和密文（SPACES-CONTRACT 第 3 节）

- **设备钥匙**：每台 Mac 一对 X25519（封存用，手机功能里已有）和一对 Ed25519（签名用，新增），都在钥匙串里。
- **成员的每个操作都由设备签名**，所以 Spark 伪造不了任何成员的动作。签名覆盖整个操作的 JSON 字节；内容类字段（素材的元数据和原文、名字、提示、理由）是**分离字段**，签名里只放它们的 SHA-256，所以撤回、移除时 Spark 可以把它们删掉（加密粉碎），签名照样能验。
- **成员和设备名单只从签过名的日志里来。** 每台成员 Mac 自己按顺序重放日志：第 1 条（创建者的设备）、`join.approve`（管理员签名，里面写明新成员的编号和两把公钥）、`device.add`、`device.remove`、`member.remove`、`member.leave`。验签和换钥匙时封给谁，都只看这份名单；`GET /v1/spaces/{id}` 里的成员列表只用来显示。所以有人在 `spaces.db` 里加一行设备，它既不能替成员签名，也拿不到下一代钥匙（Spark 会因为少了这台设备的钥匙包拒绝换钥匙，Mac 就知道名单被改过）。当前代数也按日志里的换钥匙操作算，Spark 报的代数更低时不用。参考实现是 `space_member.replay`。
- **空间钥匙**：32 个随机字节，带一个代数 `epoch`，由创建者的 Mac 生成，封存给每台成员设备（`mlwrap1.`），封好的包存在 Spark 上。换钥匙时新一代的钥匙再封给剩下的设备，同时存一个「代际链」（`mlelink1.`：上一代钥匙用新一代加密），拿到最新一代的成员就能一路往回走，读到全部历史，新加入的成员也一样。
- **派生钥匙**（都在 Mac 上算，Spark 从来拿不到空间钥匙本身）：
  - 空间整理库的库钥匙 `HMAC-SHA256(K_e, "mindloom-space-store-v1")`，每一代不同，换钥匙后整理库当场重新加密；
  - 空间的遮号钥匙 `HMAC-SHA256(K_1, "mindloom-space-mask-v1")`，取自第一代，所以同一个号码换了钥匙也还是同一个占位符；
  - 每条素材一把随机的数据钥匙，用当代的空间钥匙包起来（`mlikey1.`），它加密原件（`MLB1…`）和这条素材给成员看的字段（`mlenc1.`）。
- **撤回或移除**会删掉这条素材的数据钥匙包、它的原件密文和加密字段：别处留着的任何密文副本都成了废纸（加密粉碎）。
- 格式、AAD、HKDF 标签的精确定义在 `spark/organizer/space_crypto.py`（Spark 检查的部分）和 `spark/organizer/space_member.py`（成员设备做的部分，Mac 照着实现）；两端共用的测试向量是 `privacy/space_vectors.json`（`privacy/make_space_vectors.py` 生成，两端测试都断言它的 SHA-256）。Spark 的服务代码从不导入 `space_member.py`（有测试检查）。

## Spark 上每个空间存了什么

`<数据目录>/spaces/` 目录 0700，文件 0600：
- `spaces.db`（普通 SQLite：没有成员在线时也要能收加入申请、记操作，所以它不加密——但里面只有编号、角色、时间、类型和密文，没有明文内容）：
  - **操作日志**：服务器定序（`seq`），按 `op_id` 幂等，成员可以拿成员列表里的公钥逐条验签；
  - 每一代的**钥匙包**、代际链、每条素材当前的数据钥匙包；
  - 邀请（只存一次性密码的哈希、到期时间、钉住的主机公钥）和加入申请；
  - 下架申请、提议、隐藏、存一份、负责人、审计记录。
- `<空间编号>/blobs/`：原件密文，只有成员的设备打得开。
- `<空间编号>/organizer.db`：这个空间的整理库（SQLCipher），只有成员的 Mac 借出钥匙时才打开；旁边的 `store.keyid`、`store.maskid`、`store.epoch` 是钥匙编号和代数，不是钥匙。

## 共享空间怎么整理

1. 一位成员的 Mac 借出钥匙（`POST …/organizer/lease`，给当代的库钥匙和遮号钥匙）。钥匙只在内存里；这个成员的 Mac 一段时间（`ORGANIZER_UNLOCK_LEASE_S`，默认 600 秒）没有请求、有人锁上、换了钥匙或者 Spark 重启，整理库就锁上。
2. 有贡献权限的 Mac 把新共享的素材的整理内容送来（遮过号码的文字、缩小的图，格式和个人空间的 `POST /v1/items` 一样），只收这个空间里正在共享、而且修订号对得上的素材。Spark 收到后再遮一遍号码。
3. 同样的 Skills（读图、读文件、切分、归事件、写简介、定期整理、人物整理、首页排序、画线索图、搓绳）把**所有成员共享的素材**拼成共享的事；共享的事同样有线索图（`map`）、维度（`facets`），空间同样有绳（`ropes`）和关系（`relations`），都只引用这个空间里的素材。成员撤回或移除一条素材时，空间的图里以它为出处的结、列过它的线、引它原话的牵制一起去掉（规则和个人空间相同，见 PRIVACY.md）。
   - 一个人「共享这件事」时，这些素材在他自己的 Mac 上本来就归在同一件事里（同一个 `origin_matter_id`）。这是分享者自己整理过的结果，整理器把它当作提示：空闲时，如果这一包素材（至少 3 条）的大半已经在某件共享的事里，剩下那条却被放到别处或没归档，就把它挪进来。挪进来的仍算整理器放的，所以定期整理照样能把它和别人那份合并；被整理器切成几件事的素材不动；维护者手动移出或放好的不动；每条最多挪一次。这一步不调模型，排在成股整理和空闲画图之前，所以绳和图看到的是挪好之后的事。
4. 成员的 Mac 拉取结果（`GET …/organizer/state`，和个人空间的 `/v1/state` 一样，外加 `same_as` 和 `busy`）。
   - `same_as`：「同一件事」——每件共享的事，按成员列出它的素材来自这个成员个人空间的哪件事（送整理时带的 `origin_matter_id`）。个人首页据此显示「共享版更完整 · +N 条，来自 …」。
   - 事实冲突时并排列出来源，不悄悄选一个（简介的每条事实都带出处素材）。

没有成员在线，整理就等着；采集从不受影响。撤回或移除的素材：整理库开着就立刻清除，锁着就在下一次借钥匙时最先清除。

## 流程

**创建**：空间要么个人拥有、要么组织拥有；名字（加密）、所在的 Spark、规则（撤回窗口、能否存一份、原件给成员还是只给文字、成员离开时贡献怎么办：组织空间保留，小组空间由贡献者选）。组织由第一位管理员创建；建议再加一位管理员（规则 `recovery_admins: 2`，Spark 只记这条规则，恢复用的钥匙包就是管理员设备上的普通钥匙包）。

**邀请和加入**：
1. 管理员的 Mac 生成邀请码（二维码）：空间编号、Spark 地址、钉住的 Spark 主机公钥、一次性密码、7 天到期。**密码只在两台 Mac 之间，Spark 从头到尾收不到**：Spark 只存「门票」的哈希（门票 = `SHA-256("mindloom-space-invite-gate-v1" ‖ 密码)`）；邀请里钉的主机公钥必须是这台 Spark 自己的（`GET /v1/spaces/host-keys`）。
2. 受邀的 Mac 经 Spark 发加入申请：它的两把设备公钥，用它自己的签名钥匙签名；旁边带门票（Spark 核对哈希、把邀请作废）和一个绑定值：用密码派生的另一把钥匙对申请的原始字节做的 HMAC（`space_member.invite_binding`）。Spark 存下绑定值但算不出它，所以没法把自己的设备绑到这个邀请上。带着密码本身来的申请直接拒收。名字封给发邀请的那台设备，Spark 打不开。邀请用一次就作废；门票错 10 次邀请锁死。成员编号在整台 Spark 上绑定第一次用它的设备钥匙：拿着邀请码用别人（比如组织管理员）的成员编号加入会被拒（`member_id_taken`）。
3. 管理员的 Mac 显示「同意 / 拒绝」（两边屏幕上核对设备指纹），发邀请的那台 Mac 先核对签名和绑定值，对不上就不让同意；同意时把空间钥匙封给新设备，并在签名的 `join.approve` 里写明新成员的编号和两把公钥（不一致 Spark 拒收：`approve_mismatch`）。
4. 新成员同步：取钥匙包，顺着代际链往回走，读操作日志。

一个人的第二台 Mac 不走邀请：由他已有的设备签 `device.add`，把钥匙封给新设备。拿着邀请码冒充已有成员会被拒（`member_exists`）。

**共享、撤回、移除、隐藏、删除**：见上面的表。共享规则（「以后新归进来的也共享」）属于设它的成员，别人改不了也清不掉。离开的成员知道当代钥匙，所以离开后空间进入「待换钥匙」，管理员的 Mac 换过钥匙之前，新的共享会被拒（`rotation_pending`），Mac 把它们留在队列里；移除成员和换钥匙在同一个操作里完成，没有空档。

## 接口

所有接口仍然要链路令牌（`Authorization: Bearer`，经自己的 SSH 隧道）。共享空间不看个人库的锁和访问凭证：成员靠设备签名认，个人库锁着也能用共享空间，反过来也一样。

**签名的请求**（读、上传、整理）带四个头：`X-Mindloom-Device`、`X-Mindloom-Date`（Unix 秒，前后 5 分钟内）、`X-Mindloom-Nonce`（16–64 个 base64url 字符，15 分钟内不能重复；用过的 nonce 记在 `spaces.db` 里，Spark 重启也认得）、`X-Mindloom-Signature`，签的是

```
"mindloom-space-req-v1\n" + 方法 + "\n" + 路径（含 ?查询）+ "\n" + 日期 + "\n" + nonce + "\n" + hex(SHA-256(请求体))
```

**签名的操作**：`{"op": base64url(JSON 字节), "sig": base64url(Ed25519("mindloom-space-op-v1\n" + JSON 字节)), "enc"?: "mlenc1.…", "wrapped_dk"?: "mlikey1.…"}`，JSON 是
`{"v":1,"space_id","op_id","type","member_id","device_id","created_at","epoch"?,"enc_sha256"?,"wrapped_dk_sha256"?,"body":{…}}`。

| 方法 路径 | 谁 | 作用 |
|---|---|---|
| `GET /v1/spaces/host-keys` | 令牌 | 这台 Spark 的 SSH 主机公钥（邀请钉住用） |
| `POST /v1/orgs` | 创建者设备自签 | 建组织（`org.create`） |
| `GET /v1/orgs/{id}` · `POST /v1/orgs/{id}/ops` · `GET /v1/orgs/{id}/audit` | 组织管理员 | 组织概况、`org.admin_add` / `org.admin_remove` / `org.policy`、整个组织的审计记录 |
| `POST /v1/spaces` | 创建者设备自签 | 建空间（`space.create`，日志第 1 条） |
| `GET /v1/spaces` | 已知设备 | 这台设备所在的空间、组织、等待中的加入申请 |
| `GET /v1/spaces/{id}` | 成员 | 概况：规则、代数、成员和设备公钥、我的角色和权限、计数、整理库状态 |
| `POST /v1/spaces/{id}/ops` | 成员（逐条验签、逐条查权限） | 一次最多 50 条，逐条返回 `{ok, seq, duplicate, effects}` 或 `{ok:false, status, error}` |
| `GET /v1/spaces/{id}/ops?since=&limit=` | 成员 | 按游标取操作日志；素材的当前数据钥匙包附在它的共享操作上；别人的「隐藏」不给 |
| `GET /v1/spaces/{id}/keys` | 成员 | 这台设备的钥匙包（每一代）、代际链、当前代数 |
| `GET/PUT /v1/spaces/{id}/item-keys` | 成员 / 贡献 | 查还没包到当代的旧素材钥匙（`?stale=1`）、提交重新包好的 |
| `PUT/GET /v1/spaces/{id}/blobs/{blob_id}` | 贡献 / 成员 | 原件密文（`MLB1` 开头，≤ 36 MB）；一天内没被共享操作认领的上传会删掉 |
| `POST /v1/spaces/{id}/join` · `GET …/join/{request_id}` | 持邀请码的设备 | 加入申请、查自己的申请 |
| `GET …/join-requests` · `GET …/invites` · `GET …/audit` | 管理 | 待处理的申请、邀请状态、审计记录（只有记录，没有内容） |
| `GET …/takedowns` · `GET …/proposals` | 成员（维护看全部） | 下架申请（含到期时间）、提议队列（含整理器的 AI 提议） |
| `POST …/organizer/lease` · `POST …/organizer/lock` | 成员 | 借出 / 收回整理库钥匙 |
| `GET …/organizer/pending` · `POST …/organizer/items` | 贡献 | 还没送整理的素材、送整理内容 |
| `GET …/organizer/state?since=` | 成员 | 共享的事（同 `/v1/state`）+ `same_as` + `busy` |
| `POST …/organizer/decisions` · `POST …/organizer/questions/{qid}/answer` | 维护 | 直接改共享的事、回答整理器的提议 |

操作类型：`space.meta`、`space.policy`、`space.archive`、`invite.create`、`invite.revoke`、`join.approve`、`join.reject`、`member.role`、`member.remove`、`member.leave`、`member.profile`、`device.add`、`device.remove`、`epoch.rotate`、`item.share`、`item.withdraw`、`item.delete`、`item.remove`、`item.hide`、`item.fork`、`item.unfork`、`takedown.request`、`takedown.resolve`、`takedown.withdraw`、`matter.share`、`matter.unshare`、`matter.handover`、`share_rule.set`、`share_rule.clear`、`proposal.create`、`proposal.resolve`、`proposal.withdraw`、`agent.access`。Spark 自己写的记录只有一种：`system.remove`（隐私下架到期未处理时由 Spark 执行），它没有签名，成员只在它**删东西**时认它。每种操作的字段和错误码见 `spark/organizer/spaces.py` 里对应的处理函数（`h_<类型>`），可运行的样例见 `spark/tests/spacekit.py`（一台用 Python 扮演的成员 Mac）。

## 依赖

新增 `cryptography`（≥ 42；Apache-2.0 或 BSD-3-Clause；macOS 和 Linux aarch64 都有现成 wheel；不联网、不上报），Spark 只用它验 Ed25519 签名；测试和参考实现用它做 X25519、HKDF、ChaCha20-Poly1305。

## 诚实的边界

- `spaces.db` 不加密：没人在线时 Spark 也得能收加入申请、记操作。里面有编号、角色、时间、素材类型、音频片段的起止时间，没有内容。同一台 Spark 账号下的人能看到「谁在什么时候共享了几条」，看不到是什么。
- Spark 能检查密文的外形，证明不了它真的加密过；「真的加密了」由 Mac 端测试保证。
- 空间整理库开着的时候，Spark 拿着库钥匙和遮号钥匙（和个人空间 v6 同样的已知限制：短占位符可以被持钥匙的人穷举）。
- 撤回之前已经被成员同步到自己设备上的内容，只能靠成员的 Mac 在下次同步时删掉。
- 撤回或移除过的素材，不能用同一个编号再共享进同一个空间（可以共享一份快照）。
- 成员之间目前经各自的 SSH 连到同一个 Spark 账号；给队友的受限密钥（只能转发到这个服务）还没做。能改 `spaces.db` 的人可以让 Spark 拒绝服务、乱报名单，但伪造不了成员的操作、拿不到钥匙：成员的 Mac 只认签过名的日志。
- 成员的 Mac 从日志重建的是「谁、哪台设备」，不重算每个人的角色：角色检查在 Spark 上。
- 组织管理员被移出组织后，在还有别的管理员的组织空间里降为贡献者；如果他是某个空间唯一的管理员，Spark 手里没有钥匙，没法把空间交给别人，组织概况里会列在 `former_admins` 下，等组织里持有钥匙的管理员接手（组织恢复用的钥匙托管还没做）。
- 共享包里分享者的标题等提示只给成员看（加密），整理器看不到，整理只看素材本身。
- 两位成员说法不一致时，简介按现有规则写「现在的状态」，每条事实都带出处素材；把冲突的说法并排摆出来由 Mac 端按出处显示，Spark 端没有专门的冲突检测。
- 在共享空间里，「我」指这条素材的贡献者：Spark 主人在 `ORGANIZER_OWNER_ALIASES` 里配的名字不用于共享空间。
