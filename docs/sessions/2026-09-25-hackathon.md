## 关键决定（产品与技术）

**产品：一个私有的「耳朵 + 记忆」，也就是「语音版的苹果相册」，个人使用。**

- **收：**
  - 自动收的只有声音：任意 App 里的 Fn 口述、线上会议按 App 内录、线下用麦克风录。
  - 其他带信息的内容（文字、截图、PDF/文档、音视频）粘贴或拖进 App。
  - 每条都标来源 App。
  - 「在任何地方选中后连按两次 ⌘C」必须支持所有 App，只读剪贴板，不写入、不模拟按键。放在决赛前做。
- **整理（在用户自己的 Spark 上）：**
  - 事件照相册「回忆」的最小设计：自动创建，只有一层；内容是自动标题、一句「现在到哪一步」、相关的人、按时间排的原件。
  - 事件之间不建关系，只有一种默认排序（重要性加时效）。
  - 人物按声音识别，名字由用户起；拿不准时偶尔问一句「是同一个人 / 同一件事吗」。
- **看：**
  - 首页是事件列表加一排人物，另有事件页和人物页。
  - 整理错了就在界面上原地改，不走入口。
  - 入口收进来的内容一律当信息，不当命令执行。
- **出和回：**
  - 一件事导出成一段纯文字。
  - 在外面产生的结果从同一个入口带回来，标明来源。
  - 不做内置的对话 agent。
- **Skill：** 不是产品的骨架。只为比赛把天然适合的部分做成 Skill：event-assign（归事件）、event-brief（写标题和进度）、home-rank（首页排序）、screenshot-read（读截图），另有可选的 recall。
- **隐私边界改写（边界本身负责人已同意，写进 PRD 的文字还待审阅）：**
  - 音频、声纹、词典永远不离开 Mac。
  - 文字、用户提供的材料和元数据，只经一条可撤销的 SSH 加密链路发到用户自己的 Spark，只用于整理。
  - 录音、识别、插入和搜索都不依赖这条链路。
  - 开发期只发合成数据。
- **开源方式：** 新建一个干净历史的仓库，Apache-2.0，提交前改名并公开。

**技术：**

- Spark 上没有 Docker，改用用户态 vLLM。
- 主力模型暂定 Qwen3.6-35B-A3B（NVFP4）。DeepSeek-V4-Flash 质量相近但慢约 3 倍，只作对比。Step3-VL-10B 保留为 StepFun 组件参与对比。
- 每类任务用哪个 Skill 由程序直接指定，不靠模型自己去找。
- 整理结果以「建议」的形式回到 Mac：只新增，不覆盖原件；用户的纠正永远优先。
- Codex 那个未构建过的提交里只挑三处修复来用，不采用它的手动表单式事件和人物界面。

## 实测数字

- **已装 bestASR（日志聚合，不含内容）：** 松手到插入 P50 362 ms，P95 863 ms（n=34）。
- **Qwen3.6 单机：** 输出约 100 tok/s，读入 5.7k–7.2k tok/s。
- **DeepSeek-V4-Flash 双机 TP2：** 输出约 34 tok/s，读入 1.4k–2.3k tok/s；关闭思考后，一次 JSON 结构化输出约 2.8 s。
