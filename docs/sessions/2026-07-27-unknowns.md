## 关键决定（产品与技术）

下面这些都是会话里提出的方向。会话在第一个访谈问题处结束，负责人还没有逐项确认，也还没有写回 PRD。

- **定位**：本地听写和会议笔记这两层已经商品化或非常拥挤，唯一站得住的差异化是第三层，即「跨场景、跨会话、持续积累的人物身份和语音记忆」。口述优先只作为工程上的第一块，不作为市场定位。
- **人物层的 UX 隐喻**：「语音版的苹果相册人物」。被动积累、端上处理、「这是同一个人吗」的确认流、合并与拆分纠错、换模型后重新聚类但人物不变，这些和已有设计里的 SessionSpeaker/Person/不可变纠错记录一一对应。
- **生死实验**：任务 6.7（在真实难例语料上、保守阈值下测身份一致性）被明确为整个产品的 go/no-go。
- **版本分层**：
  - V1：输入、记忆、人物。范围不变，只重写定位。
  - V1.x：做一个本地 MCP server，把历史、人物和检索以只读方式开放给本机 agent。
  - V2：语音交互面和 iPhone 同步，先挂旗，不做设计。
  - V3：输出方向。会议 copilot 先做到「递条子」而不替用户开口；声音克隆必须放在同意框架下。先挂旗。
- **推进流程**：一次只聊一个话题（历史/检索/组织 → 口述体验 → 人物层 UX → MCP 边界 → 未决裁决），每聊完一个就写回 PRD。实证工作并行推进。之后改写技术方案，开新的 OpenSpec change。
- **多模型分工**：按「实现者/评审者」分工，不按模块分。两个模型不同时改同一个工作树。评测和基准这类「裁判代码」由评审方抽查，避免自己产出、自己验证。
