## 目标

bestASR 此前的开发覆盖面较广，但口述这条主路径还达不到日常可用。这次的目标是把 macOS 本地口述做到能天天用，对标同类商业口述产品。考核看四个维度：准确率（重点是中文和中英混说）、速度、资源占用（内存、CPU、磁盘）、功能完整性。另外交互和界面也要达标。人物和事件并列的长期愿景（「语音版的苹果相册」）明确推迟，等口述和交互彻底解决之后再做。

## 关键决定（产品与技术）

**产品**

- V1 的发布门槛收窄为「日用级口述」，全程本地运行。会议录音、内录、导入、人物、事件等功能冻结：代码和需求编号都保留，只是不再投入（见 PRD V1.6 §0.1）。
- 之前没提交的 69 个文件原样存进 `archive/codex-wip-20260918` 分支。
- 交互方案：
  - 屏幕底部一个小胶囊，没有按钮；字幕默认显示，可以改成悬停时才显示。
  - Fn 按住说话，轻点一下进入免手持。
  - Fn+Shift 翻译后插入；按住 Fn 时连按 Shift 可切换目标语言。
  - Fn+空格是指令：有选中文字就对选中内容操作，没选中就生成文字并插入。
  - 暂停功能整体删除。
  - 没能写入时自动放进剪贴板，并如实提示「已复制」。
- 界面按苹果的产品思路「能删就删、只说结果、不讲实现」：首页固定一屏，历史页的筛选控件全部直接摆出来。

**技术**

- 识别器保留 Qwen3-ASR 1.7B 8-bit（MLX）加 ForcedAligner，实时字幕用 SenseVoice。同一评测集上对比过 Fun-ASR-Nano、SenseVoice、FireRedASR2，综合 Mac 上的工具链和英文召回，最终不换。
- 性能架构：
  - 在说话停顿处提前解码（投机解码），松手时直接复用结果。
  - 连续口述走完整流水线，上一段还在处理时下一段就能开始。
  - 模型推理放在专用串行执行器上。
  - 模型按需加载，空闲 10 分钟后释放。
- 润色移出插入的关键路径。整理改用个人 0.6B 8-bit 清理模型，外加一道护栏：新引入的字符不超过 1%，过不了就回落到规则清理。
- 分工原则是「交给模型的自由度，不超过模型能承担的」：
  - 翻译用系统自带的本机翻译框架。
  - 算术和单位换算用确定性代码。
  - 指令改写要过三道门：不是回显、不为空、长度不超上限。
  - 试过 4B 文本模型，没有采用。
- 投递层重建为「一条路、两个观察值」：
  - 只走一条路：⌘V 粘贴，剪贴板内容用延迟提供（promised）的方式写入。
  - 两个观察值：目标 App 确实读取了剪贴板；输入框的文本确实变了。
  - 写到哪里由松手时的前台 App 决定。
  - 有证据才报「已输入」，也不再按 App 做学习。
- 源音频的母版存 16 kHz PCM，也就是识别器实际吃进去的音频，不做有损压缩。以后所有模型类功能都读母版；回放可以另外用压缩副本。
- 重计算任务不在本机并发跑（曾因内存压力触发过一次重启）：一次只跑一个，并加内存上限和守护脚本。

## 实测数字

- **速度（松手到写入）**
  - 接手时最快一次约 3.5 s；第一轮改完后短句 0.7–1.2 s；投机解码命中时约 0.3–0.4 s。
  - 09-21：P50 545 ms，P90 635 ms。
  - 投递重建后 17 次真实口述：P50 326 ms，P90 909 ms，慢的部分在识别侧。写入本身 22–52 ms。
- **准确率**（在私有人工核对集上测，这个集不进仓库）
  - 特征修复后 CER：40 条上 3.20% → 2.71%，48 条上 4.92% → 3.74%。
  - 8-bit 与 bf16 基本持平：3.74% 对 3.78%。
  - 新旧版本盲测 20:4，偏向新版。
- **否决项的数据**
  - 个人识别器微调后 CER 从 2.57% 升到 8.43%。
  - 自动词表 4.06% 和 4.65%，都不如手工词表的 3.74%。
- **清理模型**：0.6B 对比 1.7B，时延 193 对 241 ms，内存 630 对 948 MB。
- **资源**
  - 空闲时 CPU 约 0%。
  - 模型加载后的常驻内存约 5.2–5.5 GB，空闲 10 分钟后降到约 0.93 GB；启动峰值 9.9 GB。
  - 日志从每分钟 47,300 行降到 1,581 行。
  - 已存录音从 578 MB 压到 104 MB。
- **翻译和指令**：120–320 ms。
- **结构**
  - 投递栈从 4,546 行减到 663 行。
  - App 模型从 12,045 行减到 3,357 行。
  - 主视图从 6,271 行减到 568 行。
  - 173 个状态迁入 13 个职责对象。
- **测试**：包测试 540 个、App 测试 144 个全部通过；UI 测试 19/19。

## 遗留问题与下一步

1. **速度 P90（已定为下一项）**：没有停顿的短句要到松手才从头解码。目标是 P90 ≤ 600 ms。
2. **资源**：启动峰值 9.9 GB 和空闲时一大块内存的归属还没定位；历史记录收尾时还有一次约 3.8 s 的开销。
3. **准确率**：
   - 还没有「说得快、含糊、中英混说」的专项评测子集。
   - 停顿处标点偏多。
   - 实时字幕随识别更正同步更新，还没做完。
4. **本地 1.7B 文本模型**：总结、改短、英文措辞和常识都偏弱。
5. **代码结构**：App 模型主文件还有 3,357 行，目标 ≤ 2,000；行为迁移只做完了词典；持久层单个文件约 9.4k 行，还没动。
6. **界面**：
   - 事件、人物、历史详情页的菜单交互待改。
   - 高级设置的文案待改。
   - 首次引导流程待改。
   - UI 测试会写进真实剪贴板，需要隔离。
7. **旧录音**：迁入的旧录音暂时不能回放；回放用的压缩副本也还没做。
8. **系统设置**：键盘上的地球仪键要由用户自己在系统设置里改成「无操作」。
9. **公开前**：需要对 bestASR 再做一次隐私扫描并清理。
10. **人物加事件**：等以上各项完成并验证之后再开工。
