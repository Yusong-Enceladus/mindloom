# 能收什么：文件类型和处理位置

原则：**Mac 什么都收；图片和文件在你自己的 Spark 上读；音频只在 Mac 上处理。** Spark 收到的是遮过号码的逐字稿和文字、涂过号码的图片副本和文件的发送副本，只经你打开的 SSH 链路；图片和文件在 Spark 读完就删字节。声纹、说话人向量和词典从不发送。详细的类型清单、大小上限和评测见 [MODELS.md 的「多模态支持范围」](MODELS.md) 与 [FILE_READ.md](FILE_READ.md)。

| 输入 | 怎么进来 | 在哪处理 | 用什么 | 还不支持 / 未测 |
|---|---|---|---|---|
| 口述 | 任何 App 里按住 Fn | 只在 Mac | Qwen3-ASR（MLX）识别，插入到光标处，同时存进资料库 | — |
| 会议（线上 / 线下） | 按 App 内录系统声音，或麦克风 | 只在 Mac；Spark 只收逐字稿和分段（时间、人物 ID、你起的名字） | 识别 + FluidAudio 说话人 | 音频发往 Spark：按设计不做 |
| 会议软件导出的逐字稿 | 导入 / 拖入 | Spark | 和粘贴文字同一套规则；长会议由 item-split 切成几件事 | — |
| 导入的音视频 | 拖入 | 音轨只在 Mac；视频最多 12 张关键帧作为图片发给 Spark | 识别 + image-read | 关键帧读图质量未单独评测 |
| 图片：截图、照片、图表、幻灯片、白板、小票发票、扫描件、标签面单 | 粘贴 / 拖入 | Mac 本机读字供搜索，也用来涂掉副本里的号码；发一份缩小、不带元数据、号码涂掉的副本到 Spark | image-read（Qwen3.6-35B-A3B NVFP4）先判类型再按类型读；98 张测试图关键字段 96.2% / 98.8% | HEIC 由 Mac 转码后再发（这条路径未在评测集上跑过）；真实照片、多图、长截图、图中的提示词注入：未测 |
| 文档和其他文件：Office（含 97–2003）、OpenDocument、PDF（含扫描件）、邮件、日程、名片、电子书、压缩包、网页存档、文本 / 代码 / 数据 | 拖入 | Spark 沙箱子进程确定性解析；扫描页和内嵌图片交给 image-read | file-read 写一句概要和票据类关键字段；Mac 另外抽出文字兜底。33 种格式、115 个测试文件：金标准答案出现在读取结果里 0.82（不含 HEIC 和视频 0.91），见 [EVALUATION.md §10](EVALUATION.md#10-读文件33-种格式截止时未变) | XML 属性值没读出（0.20）、GIF 只读首帧（0.47）；真实文件评测集、.msg 真实样本：未做 |
| 粘贴的文字、聊天记录 | 粘贴 | Spark | 「名：…」行会成为人物 | — |
| 手机：织机键盘说的话；分享的文字 / 链接 / 图片 / 文档（≤ 25 MiB） | iPhone App「织机」：切到织机键盘按住说话，或在任意 App 里点「收进织机」 | 语音只在手机上识别；每一条在手机上封好（只有你的 Mac 能打开），经你自己的 SSH 密钥进 Spark 收件箱，Mac 取走、打开后作为普通素材再送去整理 | 手机本机语音识别；之后同上 | 音视频不从手机分享；App 只在 iOS 模拟器上跑过（见 [PHONE.md](PHONE.md)） |

每条素材都带来源 App（粘贴取之前的前台 App，拖入取拖拽来源，手机为 iPhone）和时间，整理结果只是建议，不覆盖原件。

注意：音频和视频不管用什么扩展名（按内容认），都从不作为字节发送：能读的在 Mac 上转成文字，其余只留在 Mac 上。压缩包在 Mac 上展开，每个成员按同样的规则处理；tar、7z、rar 和认不出的二进制文件只留在 Mac 上。Mac 读不出文字的文档只以「发送副本」发送：里面的图片涂掉号码，音视频和嵌入对象清空（见 [PRIVACY.md](PRIVACY.md)）。
