# 三组真实模型评测与接手结论

完成于 2026-09-26 23:27:28 Asia/Shanghai；2026-09-27 00:03 起只读复核。此前首轮报告保持原样。本文件没有部署地址、凭据或真人资料。

## 结论

独立后端、真实模型、向量检索、素材同步和人工改名的最小演示已跑通。三组预定评测均完整结束，无需超时恢复。**这证明工程链路可以运行，不代表复杂事件整理已经可靠。** 带技能说明在本轮开发集提高了聚类 F1、减少了格式失败和耗时，但相似项目误合并更多，不能宣称全面优于对照。

明早可开始接入 Mac 和复现演示；正式演示前，应先处理项目边界、事实的计划/完成状态、噪声归档以及失败后的保守处理。没有依据 holdout 修改提示词，也没有增加压力测试、训练或重启共享模型。

## 方法和完整性

- 同一已有 Qwen3.6-35B-A3B NVFP4 聊天服务、同一 Qwen3-Embedding-0.6B 检索服务，逐条输入，独立数据库。
- 开发集 82 条资料、9 个标注事件、4 个检查点；holdout 32 条、5 个事件、2 个检查点。共 114 条不同的虚构素材，三组累计处理 196 条次，不能写成 196 条独立样本。
- 无技能说明组保留全局数据边界、JSON schema、检索、业务校验和相同输出预算，仅移除技能正文与参考说明。因此它衡量的是这套说明在当前预算下的影响，不是纯向量基线或完全无约束模型。
- 带技能开发组和 holdout 的技能哈希一致；两组开发数据哈希一致。运行目录中的 41 个核心源码、技能和评测文件与运行前归档逐项哈希一致。
- 三组均有 `completed=true`、全部输入、全部检查点、最终状态、运行记录和分数。重新执行原评分器，与三份原始评分 JSON 完全相同。
- 预定整批任务在一小时上限前约 51 秒结束，没有触发超时、没有重跑实验。任务结束后 transient unit 被回收，查询到的默认 RuntimeMaxUSec=infinity 不表示运行上限被修改。

三组累计 592 次技能运行、622 次模型调用，服务器报告输入 1,934,893 token、输出 249,600 token。调用记录之和与 runtime 汇总一致。模型运行在本地设备，没有使用云模型付费接口；这里不统计电费和设备折旧。耗时包含归类、简介、首页排序等步骤，不是模型单流 token/s。

无技能说明组的 9 次最终失败全部发生在归类：两次尝试各用满 400 输出 token，总计 800，返回 JSON 在字符串或数组中结束。结合未闭合 JSON 与预算耗尽，这与输出被截断一致；当前日志没有保存 `finish_reason`，不能声称逐次直接读到了 length。现有代码遇到两次无效输出便新建事件，因此任务仍可排空、数据仍全部处理，但整理质量受影响。**completed=true 不等于所有技能成功。** 本次没有为了提高对照分数临时增加其预算或修改提示词。

每组只做一次顺序运行，没有多随机种子、并发隔离和置信区间；用时差异不能作为稳定的性能优势保证。

## 真实失败案例

开发集已在首轮报告记录：咖啡店装修混入妈妈家漏水，租约混入市集，门头混入周年海报，退款新旧状态被拆开；模型把“下周二开工”写成“已按计划完成”。

holdout 虽然恰好生成 5 个事件，也不等于五件事全对：

- “跳格 App 改版”事件混入作品集网站资料，作品集没有独立保留下来。
- 噪声“买燕麦奶和鸡蛋”被创建为独立事件，恰好抵消了上述缺失，使事件总数仍为 5。
- 合租工作室素材仅约定“9 月 1 日搬”，并确认转账和搬家准备，模型却写出“9月1日已搬入，费用已结，工作室业务正常推进”。来源没有实际搬入确认。

以上仅用于报告边界，不用于本轮 holdout 调参。困难干扰泄漏为 0 也不能证明所有项目边界正确，它只检查标注的指定事件对。

## 时间与能力边界

开发资料发生于 9 月 14–20 日，holdout 发生于 8 月 17–23 日，回放时钟是 9 月 26 日。没有注入每个检查点的历史时钟，会影响计划与紧迫度判断；下一轮开发实验应先解决这个方法问题。即便计划日期已过去，系统也不应无确认材料就写成已完成。

当前一条素材只能归一个事件，标注允许多事件；归类候选最多 5 个，候选只展示最近 3 条，简介仅看最近 30 条且逐条截断；没有明确不归档决策，recall 还是关键词占位。人工修改优先的工程回归已测，但完整 Mac 用户流程未验收。53 项单元测试通过不能替代这些产品能力。

## 模型适配与明早顺序

Qwen Q8 和双机 DeepSeek 在四道小型题各为 4/4。Step3 原路径为 2/4，显式原生适配后为 4/4；相同截图由 70.17 秒降至 19.16 秒，五条消息逐项匹配，但摘要仍有发言人归属错误。样本和硬件不同，不能据此发布模型总排名。完整三组评测全部使用 Qwen NVFP4，没有中途切换模型。

1. 用已有四条虚构资料重现演示，再接入 Mac 客户端并跑 Mac 测试。
2. 以开发集建立交付目标、地点、对象的边界回归，处理“相同人、不同项目”。
3. 增加受控回放时钟和事实状态，要求完成、取消等变化有确认来源。
4. 记录 finish_reason 与逐次尝试，检查归类输出预算以及失败后直接新建事件的后果。
5. 为噪声、多事件素材和语义 recall 单独设计并验收；另备未见数据，避免把已检查的 holdout 持续调成开发集。

本报告没有声称 Mac 全链路完成、最优超参数确定或多日稳定性达标。
