## 技术方向

1. 保持当前 JSON schema 路线。vLLM 官方提供结构化输出接口；schema 保证格式不等于事实正确，仍要保留引用和业务校验。[vLLM Structured Outputs](https://docs.vllm.ai/en/latest/features/structured_outputs/)
2. 向量服务应与生成服务区分。vLLM 的 pooling runner 用于嵌入类任务；不需要为了它重启已有聊天模型。[vLLM Pooling Models](https://docs.vllm.ai/en/latest/models/pooling_models/)
3. 0.6B Qwen 嵌入模型适合先补齐这条链路。应记录模型标识与维数；升级嵌入模型时重新索引，不能混用不同向量空间。[Qwen 官方模型说明](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)
4. Skills 当前以 Markdown、references 和 scripts 组织，与公开规范的基本结构一致。路由由程序固定，不能宣传为已经实现自主多智能体协作。[Agent Skills 规范](https://agentskills.io/specification)
5. DeepSeek 的历史结构化输出失败包含 `content=null` 和 `finish_reason=length`。本次运行实证表明 `chat_template_kwargs={"enable_thinking":false}` 可产生有效 JSON。该结论限于本次服务版本，不应从模型名称推断所有推理后端都相同。

## 明早的建议顺序

先复现一个完整事件链，再做界面接入。演示选交接资料推荐的“国庆前上线”：口述需求、会议确认、截图改预算、导出交接、回收回复。加入一个同人不同事的干扰事件，以及一次旧预算被新预算覆盖的更新。所有数据继续保持虚构。只有已实际验收的功能进入录屏。

暂时不要以 token/s 选择最终模型。先看归事件 F1、干扰误并、最新事实召回、过期事实率、截图发言人准确性、人工纠正能否保留，再比较处理延迟与算力占用。当前评测仍有单事件归属、文本截断、保守提问和噪声归类限制，需要把失败案例交给产品负责人判断。
